# 歌词文件走 `/song/lyric` 的 `download=1`，不另开下载路由

取歌词、QRC 解密、抹平成整行这三步在 `resolveLyric` 里已经是一条现成的路，所以存文件只是在同一个 URL 上加 `download=1`，回 `.lrc` 正文而不是 JSON 信封。

放弃的方案：独立的 `/song/lyric/download` 路由（职责更分明，但要么复制那段解码编排，要么把 JSON 路由降为薄壳）；前端拿已渲染的文本自己拼文件下载（省一次往返，却绕过了服务端唯一定义「整行版」的地方，轨选择与解密失败语义都得在前端重做一遍）。

代价写在这里，免得下一个读者按 `LyricData` 去解析文件分支：同一个端点的表示由 query 决定；`kind` 那一轨不存在时回 404、解密失败回 409，两者都不落文件。
