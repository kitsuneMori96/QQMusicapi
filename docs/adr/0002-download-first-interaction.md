# 下载优先的信息架构：一次点击、只探测首选档

这个项目实际用途是下载音乐，默认档位 SQ 无损，因此解析页的主动作被定为「下载首选音质」这一个按钮：粘贴只触发解析（识别 mid / 分享链接、拉曲目卡），**落盘必须由用户显式点击**；首屏也只探测 `F000` 一条直链，其余 16 档折叠成「其他音质」，展开时才并发探测。

放弃的方案是维持原来的「解析即全量探测 17 档 + 用户从列表里挑一行」：那样首个动作要吃 17 个上游请求，且把「这首歌有哪些档可取」的可见性当成了主界面——那是研究视图，不是下载视图。代价是折叠态下看不到 `11 / 17 可取` 这个计数，需要展开才知道全貌，这是刻意的。

另外三条同样故意，写下来以免被后人「修好」：粘贴不自动下载（误触就会落几十 MB，且多文件下载会撞浏览器权限弹窗）；歌单/专辑批量下载不在本次范围（需要新的解析能力与队列状态机，是独立一轮）；`SQ` 不可取时只在 `F000 > O801 > O800 > M800 > M500` 里降级并写明原因，**母带/杜比/全景声那一组永不自动进入降级路径**。
